Задача — классическая (дизъюнктное хранение 12‑битных квантованных весов, деквантизация на пути к тензорному умножителю), отвечаю внутри вашей абстракции. Инструменты не нужны — только доказательства.

## Модель счёта и обозначения

Машинное слово — 32 разряда: 4 байта, 2 элемента F (лэйна по 16 бит), 8 ниблов. Вне P каждая словная операция стоит 1; операция, обслуживающая k индексов, даёт 1/k действия на индекс. Вызов P даёт 4 точных произведения (p произведений на индекс = p/4 вызова). Ключевой факт об F (мантисса 11 бит): **все целые |k| ≤ 2¹¹ = 2048 лежат в F точно, а из целых в (2¹¹, 2¹²] — только чётные.** Поэтому n_i ∈ F, но «окно» точных целых кончается ровно там, где начинается 12‑й разряд.

Группа G_g — 128 индексов; T_g = Σ_{i∈G_g} x_i n_i; S = Σ_g s_g T_g — точное тождество в ℚ.

Базовая раскладка (текущая): 3 скалярных действия на индекс (сборка n, приведение к F, умножение на s_g) + 1 произведение в P.

## §1. Множитель s_g: ноль действий на индекс

**Утверждение 1.** При вычислении T_g отдельным аккумулятором на каждый индекс не приходится ни одного действия с s_g; на группу — 1 умножение + 1 сложение (на каждый выход). **Условия на границы:** (а) длина группы кратна ширине P (128 = 32·4 ✓) и четвёрки операндов согласованы с границами — ни один вызов P не пересекает границу группы; иначе на стыке до 3 индексов требуют предварительного домножения, по действию на каждый; (б) у группы свой аккумулятор (или «умножь и влей» по завершении); (в) бонус точности: одно округление s_g·T_g на группу вместо 128 округлений на индексах — строго не хуже. Переносить s_g на x_i нельзя: x переиспользуется выходами с *разными* сетками масштабов; вынос за групповую сумму универсален.

Счёт: **0/индекс, 2/группу (на выход), 0/выход сверх того.**

## §2. Одно произведение на индекс — невозможно (при раздельном хранении)

Чтобы индекс обслуживался одним произведением, нужен единый операнд a_i ∈ F с a_i = c·n_i + d' точно для всех 4096 значений. Из потолка 2¹¹: с точностью до степени двойки (поглощается s_g) и знака это форсирует a_i = ±2^k(n_i + d), d ∈ {0, 1} — сдвинуть окно, как в приёме «1024 + M», нельзя: 12‑битному целому не хватает точного диапазона F.

**Лемма 1.** Никакая перестановка байтов/битов (шире — никакое аффинное над GF(2) переразмещение битов h_i, l_i с константами) не порождает кодировку ±2^k(n_i + d) в F.
*Доказательство.* Аффинное f удовлетворяет f(p)⊕f(q)⊕f(r)⊕f(p⊕q⊕r) = 0. Возьмём входы с n = 0,1,2,3 (коды 0⊕1⊕2⊕3 = 0). Мантиссные поля кодировок величин 2^k(n+d): при d=0 — M = 0, 0, 0, 512; при d=1 — 0, 0, 512, 0; XOR мантиссных полей равен 512 ≠ 0 при любом k (масштаб сдвигает только поле порядка), знак ⊕0x8000 входит четырежды и сокращается. Противоречие. Содержательно: нормализация делает показатель переменным, а значение — неаффинным по битам. ∎

**Следствие.** Выбор ровно из двух: **(A)** 2 произведения на индекс, части не встречаются до P; **(B)** 1 произведение + арифметическая (не перестановочная) сборка лэйна n_i — не дешевле 1.5 словной операции на индекс (подготовка двух потоков по ½ + FMA по лэйнам ½).

**Ответ на п. 2: нет.** И тождество из вопроса можно улучшить: множитель 16 выгоднее унести не на x, а **в групповую константу**: Σ x(16h + l) = 16·Σ x h + Σ x l, где 16 сворачивается в 16s_g (предвычисляется при упаковке). Тогда даже на переиспользуемый x не тратится ничего, и нет риска выхода 16x за окно порядков.

## §3. Перестановка байтов: байту — да, ниблу — доказуемо нет

**Тождество инъекции:** для 0 ≤ M ≤ 1023 битовая строка 0x6400 + M (поле порядка E = 25) кодирует в F число **1024 + M**. Байт B, поставленный перестановкой в младший байт лэйна рядом с волшебным байтом 0x64, даёт элемент F, равный 1024 + B, — без арифметики; это одновременно и «приведение к F».

Перекодируем хранение при упаковке (однократно, вне пути): **b_i := h_i + 128 ∈ [0, 255]**, тогда n_i = 16b_i + l_i − 2048 и исчезает знако‑расширение.

**Утверждение 2 (байт).** Из слова с 4 байтами b_i две перестановки строят 4 лэйна f_i = 1024 + b_i: **½ действия на индекс**, ноль арифметики.

**Лемма 2 (нибл).** Чистые лэйны 1024 + l_i перестановкой байтов не строятся. *Доказательство.* Байт неделим и содержит ниблы двух соседних индексов; единственная байтовая позиция, целиком лежащая в мантиссе лэйна, — биты [7:0] (байт [15:8] задевает порядок и знак). Значит лэйн индекса i получает 1024 + αl_i + βl_{i′}, β ≠ 0, и в сумме возникает s_g·β·Σ x_i l_{i′}. Коэффициент при l_{i′} в точном S равен s_g x_{i′}; в вычисленном — содержит слагаемое s_g β x_i. Равенство линейных форм по x при всех x требует β = 0 — противоречие; никакая поправка без произведений вида x·l этого не чинит. ∎

Ниблу положена одна битовая словная операция (маска+инъекция): лэйны m_i = 1024 + l_i ценой **1 действия на индекс** (½ при трёхвходовых битовых операциях над словом).

**Ответ на п. 3: да для 8‑битной части, нет для 4‑битной** — предел приёма равен байтовой гранулярности перестановки.

## §4. Поправка ранга один: уходят все константы — и только константы

**Теорема 2.** Компонента c_i устранима поправкой ранга один (Σ x_i c_i = c·X_g, X_g = Σ_{i∈G_g} x_i) **тогда и только тогда, когда c_i ≡ c на группе** (равенство линейных форм по x равносильно равенству векторов коэффициентов). Значит: данные нибла — нет; все смещения — да, единым махом.

Собираем всё: из f = 1024 + b, m = 1024 + l:

**x·n = 16·x·f + x·m − 19456·x**, где 19456 = 16·1024 + 1024 + 2048.
*Проверка:* h = −3, l = 7, n = −41: 16·1149 + 1031 − 19456 = −41 ✓.

Отсюда T_g = 16A_g + B_g − 19456·X_g (A_g = Σ x f, B_g = Σ x m) и

**S = Σ_g [ (16s_g)·A_g + s_g·B_g − (19456·s_g)·X_g ].**

Константы 16s_g и 19456s_g предвычислены при упаковке. **X_g считается один раз на пару (группа, x‑вектор)** — 127 сложений или 32 вызова P с единичным операндом — и переиспользуется всеми выходами: это и есть законный перенос «на другой сомножитель». Сюда же бесплатно уходит любой групповой zero‑point, будь он в схеме.

**Ответ на п. 4: да** — для всех постоянных на группе смещений (2048, 1024, 128·16), целиком, одной константой −19456·s_g·X_g на группу; **нет** — для самих данных l (теорема 2).

*Оговорка о точности:* со свёрнутыми смещениями слагаемые раздуты (f ≈ 2¹⁰), и точная компенсация требует, чтобы групповые частичные суммы не округлялись; если 24‑разрядного окна не хватает, смещение вычитается по лэйнам сразу после инъекции (+½ действия на индекс), возвращая исходный масштаб слагаемых, с соответствующей заменой константы.

## Итоговая схема (точная, хранение прежние 12 бит)

| статья | было | стало |
|---|---|---|
| на индекс, скалярная арифметика | 3 | **0** |
| на индекс, словные операции | — | **≈1** (перестановки ½ + битовая для ниблов ½–1) |
| на индекс, произведения в P | 1 (¼ вызова) | **2 (½ вызова)** |
| на группу на выход | 0 | **5–6** (3 умножения на предвычисленные константы, 2–3 сложения) |
| на (группу × x‑вектор), амортизируется по выходам | — | **один агрегат X_g** |
| на выход сверх групп | 0 | **0** |

Если пропускная способность P избыточна хотя бы вдвое относительно скалярного пути (ради этого P и существует), внепутевые действия сокращаются втрое, а скалярная арифметика на индекс исчезает полностью. Если же P насыщен — вариант (B) §2: 1 произведение + ≈2 словные операции на индекс, всё равно лучше базовых трёх.

## §5. Нижняя граница

**Теорема 3.** В данной модели любая точная схема выполняет вне P **не менее 1 словной операции на индекс** (за один проход по данным), при любом способе хранения объёмом 12 бит на величину.
*Доказательство.* (i) Ни одно хранимое слово не годится операндом P дословно: при плотной 12‑битной упаковке 16‑битный лэйн содержит ≥ 4 бита чужой величины с полной энтропией; все 16 бит лэйна влияют на его значение, и по аргументу линейных форм (как в лемме 2) чужой вклад неустраним. Попутно: 12‑битные поля нельзя упаковать байтово‑выравненно — 8 ∤ 12, смещения полей чередуются 0, 4 (mod 8). (ii) Каждое операндное слово (2 лэйна) требует хотя бы одной записывающей операции; при p произведениях на индекс нужно pK/2 операндных слов ⇒ ≥ p/2 операции на индекс. (iii) p = 1 исключено §2 в перестановочном классе (а с арифметикой стоит ≥ 1.5), значит p ≥ 2 и граница равна 1. ∎

Схема §4 достигает границы с точностью до множителя ≤ 1.5 — оптимальна по порядку и почти по константе.

**Меняется ли граница при перекодировке (12 бит неизменны)? Нет.** Шаги (i)–(ii) не используют, *что* закодировано — только 12 < 16. Перекодировка меняет константу: смещённое b = h + 128 убирает знако‑обработку; разбиение 8+4 — единственное, отдающее максимум байтовой перестановке. Обнуляет границу только размен память↔путь: **16 бит на величину** — хранится готовый лэйн F (само n_i, оно в F точно), 0 действий вне P, 1 произведение, s_g по §1. (При пакете из M векторов x распаковка амортизируется до 1/M на индекс×вектор, но за один проход граница 1 точна.)

## Сводка ответов

1. **Да**: 0 действий на индекс; условия — кратность границ ширине P, непересечение вызовов P границ групп, отдельный аккумулятор; 2 действия на группу на выход.
2. **Нет**: одно произведение недостижимо (лемма 1 + потолок 2¹¹); оптимум — два произведения, а 16 сворачивается в 16s_g, не в x.
3. **Да для байта** (0x6400 + M ↦ 1024 + M, ½ действия/индекс), **доказуемо нет для нибла** (лемма 2).
4. **Да для констант**: все смещения уходят одной поправкой −19456·s_g·X_g; для данных l — невозможно (теорема 2).
5. Граница — **1 словная операция на индекс**; инвариантна к перекодировке при 12 битах, обнуляется при 16.

(В реальном референте это в точности конвейер Marlin/AWQ‑класса: PRMT‑инъекция в 0x64‑магию, LOP3 для ниблов, zero‑point и смещения — в rank‑1 член на масштабах группы.)
