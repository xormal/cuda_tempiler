ОПРОВЕРГНУТАЯ ПОПЫТКА (сохранена намеренно): свип регистрового бюджета через -maxrregcount
=========================================================================================
Первая редакция `cc_ab.py regsweep` меняла бюджет флагом `-Xptxas -maxrregcount=N`.
Ядро: bwd<128,64,256,noESK>, 256 потоков, __launch_bounds__(256, 1).

  бюджет    рег   стек   отчёт Б   LDL/STL   вердикт
     176    173      0     0/0      0/0    ВЛЕЗАЕТ
     179    173      0     0/0      0/0    ВЛЕЗАЕТ
     180    173      0     0/0      0/0    ВЛЕЗАЕТ
     183    173      0     0/0      0/0    ВЛЕЗАЕТ
      96    173      0     0/0      0/0    ВЛЕЗАЕТ     <-- ФИЗИЧЕСКИ НЕВОЗМОЖНО
     120    173      0     0/0      0/0    ВЛЕЗАЕТ
     136    173      0     0/0      0/0    ВЛЕЗАЕТ
     152    173      0     0/0      0/0    ВЛЕЗАЕТ
     168    173      0     0/0      0/0    ВЛЕЗАЕТ
     172    173      0     0/0      0/0    ВЛЕЗАЕТ

173 регистра при бюджете 96 невозможны. Причина: `-maxrregcount` ИГНОРИРУЕТСЯ для функции с
`__launch_bounds__` -- launch_bounds имеет приоритет. То есть свип НИЧЕГО не менял, а инструмент
десять раз уверенно напечатал "ВЛЕЗАЕТ" и на первом заходе был прочитан как ОПРОВЕРЖЕНИЕ модели
R = MaxLive + 7 (якобы "нет разлива при бюджете ниже порога"). Модель не опровергалась -- опыт
не ставился.

ПОЙМАНО арифметикой: REG > объявленного бюджета -- признак того, что бюджет не применён.
ИСПРАВЛЕНО двумя правками:
  1. бюджет меняется через СВОЙ `__launch_bounds__(threads, minb)` у обёртки с тем же телом
     (`BWD_ENTRY_TU` в cc_ab.py) -- единственный работающий способ;
  2. в `regsweep` добавлена проверка "REG > бюджета -> БЮДЖЕТ НЕ ПРИМЕНЁН", такие строки
     исключаются из кривой и печатаются отдельной строкой "!!".
Правильный свип -- data/ccab_regsweep.txt.

Урок в жанре этого каталога: инструмент, у которого ручка не подсоединена, не даёт "меньше
данных" -- он даёт ДРУГОЙ ОТВЕТ, с той же уверенностью, и этот ответ выглядел как научный
результат ("модель опровергнута на боевом ядре").
