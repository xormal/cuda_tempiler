ПЛОМБА ПРОТИВ МЁРТВОГО КОДА: ЧТО ЗАМЕРЕНО (все числа -- sm_70, nvcc 12.8.93, -O3)
=================================================================================

1. ПУСТАЯ ВСТАВКА asm volatile("" : "+f"(x)) НЕ РАБОТАЕТ -- И ВРЁТ БЕЗЗВУЧНО.
   Тело: 8 значений a[i]=0, пломба, затем s += exp2f(a[i]-1.5f).
   пустая вставка, SEAL=0 : команд SASS = 16, MUFU = 0
   пустая вставка, SEAL=1 : команд SASS = 16, MUFU = 0
   -> БАЙТ В БАЙТ одинаково. Значение свёрнуто в константу:
              /*0040*/                   MOV R5, 0x403504f2 ;
              /*0060*/                   STG.E.SYS [R2], R5 ;
   А В PTX ЗАВИСИМЫЙ ex2 СОХРАНЁН -- то есть NVVM пломбу УВАЖАЕТ, сворачивает ptxas:
      ex2.approx.f32 в PTX: 8
   ВЫВОД (шире этого инструмента): ПРОВЕРКА БАРЬЕРА ПО PTX ДАЁТ ЛОЖНОЕ ПОДТВЕРЖДЕНИЕ.
   Барьер проверяется ТОЛЬКО по SASS.

2. ПЕРЕБОР БАРЬЕРОВ: что ptxas сворачивает, а что нет (команд SASS без/с пломбой)
   asm("")  "+f"                  16 ->   16   СВЁРНУТО (пломба не работает)
   asm("") + "memory"             16 ->   16   СВЁРНУТО (пломба не работает)
   mov.f32 %0,%0                  16 ->   16   СВЁРНУТО (пломба не работает)
   add.f32 %0,%0,0                16 ->   16   СВЁРНУТО (пломба не работает)
   max.f32 %0,%0,-inf             16 ->   16   СВЁРНУТО (пломба не работает)
   prmt.b32 %0,%0,%0,0x3210       16 ->   24   ДЕРЖИТ
   fma.rn %0,%0,1,0               16 ->   24   ДЕРЖИТ
   or.b32 %0,%0,0                 16 ->   16   СВЁРНУТО (пломба не работает)
   Держат ДВА: prmt.b32 (перестановка байт) и fma.rn (умножение на 1). Выбран prmt --
   он не занимает конвейер FP32, который в наших ядрах и без того связан софтмаксом.

3. prmt.b32 d,a,a,0x3210 -- ПОБИТОВОЕ ТОЖДЕСТВО, ПРОВЕРЕНО НА КАРТЕ (V100, карта 1)
   PRMT-ПЛОМБА: проверено 65536 слов (вкл. +-0, денормали, inf, NaN, sNaN); расхождений = 0 -> ПОБИТОВОЕ ТОЖДЕСТВО

4. ЦЕНА ПЛОМБЫ на эталонном ядре demo_phase_kernel.cu (26 опломбированных слов на виток):
   1856 -> 1888 команд SASS, +1.72 %. Пломба стоит в ОБОИХ вариантах (база и стрип),
   поэтому из ОТНОШЕНИЯ времён сокращается в первом порядке.

5. ВТОРОЙ КАПКАН, КОТОРЫЙ ПЛОМБА НЕ ЗАКРЫВАЕТ: CSE.
   Пломба делает значение непрозрачным, но НЕ делает его УНИКАЛЬНЫМ. Восемь одинаковых
   непрозрачных acc[i] дают восемь ОДИНАКОВЫХ выражений exp2f(acc[i]-m), и компилятор
   склеивает их в одно. Замерено на demo_phase_kernel.cu со снятым первым умножением:
       MUFU.EX2:  9 (база)  ->  2 (снято, ПРИ ПОСТАВЛЕННОЙ ПЛОМБЕ)
   Лечится подстановкой FMHA_PHASE_ELSE с РАЗЛИЧНЫМИ значениями (различные константы +
   пломба: склеивать нечего).
