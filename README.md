# ТЕМПОЛЯТОР

**Что это.** Инструмент, который берёт наивно написанное вычислительное ядро и выдаёт
переуложенное под конкретную архитектуру — вместе с паспортом, по которому его число можно
оспорить. Знание об архитектуре не размазано по коду: оно собрано в **плагин**. Сегодня
плагинов два: боевой **Volta / sm_70** (Tesla V100) и **каркас Ampere / sm_80** (A100), у
которого честно нет ни одного замера.

**Чем это НЕ является.** Это не транслятор исходников: продукт **порождает** ядро по
объявленной операции, а не переписывает то, что вы прислали. Парсера C++ здесь нет и в
версии 1 не будет. Незнакомое ядро получает **отказ**, а не плохой код.

---

## Вход и выход

```
kernels/naive/gemm_fp16.cu          ВХОД: наивный .cu с блоком TEMPO-OP внутри
        |
        |  recognize   блок TEMPO-OP -> спецификация операции (+ сверка с сигнатурой пуска)
        |  space       произведение осей, объявленных ПЛАГИНОМ
        |  prune       ресурсный вердикт и модельная граница -- БЕЗ ЕДИНОЙ СБОРКИ
        |  emit        скелет + параметры -> текст ядра
        |  build       регистры / разлив / КАДР СТЕКА -- три РАЗНЫХ числа
        |  verify      проверки по машинному коду ДО секундомера
        |  measure     гейт корректности, потом ДВЕ планки парными отношениями
        v
kernels/generated/<arch>/<op>/      ВЫХОД: исходник ядра + отчёт
kernels/shipped/<op>/<arch>/        ЗАМОРОЖЕННАЯ поставка: kernel.cuh, launch.cuh,
                                    dispatch.inc, select.py, manifest.json, INTEGRATION.md
```

## Одна команда до первого числа

```bash
make doctor                 # что найдено в окружении и какие есть плагины
make gates                  # гейты непротекания G1..G11 (карта не нужна)
make selftest               # самопроверки плагинов И существующих инструментов
make laws                   # РЕЕСТР ЗАКОНОВ: опись, проверки, сверка чисел с телами отчётов
python3 -m tempo.cli recognize kernels/naive/gemm_fp16.cu 4096 15360 3840
python3 -m tempo.cli space --arch sm70 -M 4096 -N 15360 -K 3840
```

Замеры (`bench/`) требуют **свободной карты**: продукт отказывается мерить при соседе на
карте, и это не перестраховка — замер с соседом недействителен.

## Как запустить на СВОЁМ ядре

1. Положите наивный `.cu` в `kernels/naive/`. Внутри — блок `TEMPO-OP` (образец:
   `kernels/naive/gemm_fp16.cu`). Блок живёт **в исходнике**, а не рядом с ним: описание
   рядом неминуемо разъедется с кодом, поэтому `recognize` ещё и сверяет его с сигнатурой.
2. `python3 -m tempo.cli recognize <файл> M N K` — если операция не объявлена, вы получите
   отказ с названной причиной.
3. `python3 -m tempo.cli space --arch sm70 -M .. -N .. -K ..` — что перечислено, что отсечено
   и **почему именно**.
4. `python3 -m tempo.cli emit --arch sm70 ... --out DIR` — порождённый исходник.
5. Дальше — сборка и замер по дисциплине из `docs/MEASURE_DISCIPLINE.md`.

Ваша операция не `gemm`? Тогда нужен **скелет** под неё в плагине. Скелет — это 100 %
архитектурный код, и он через границу плагина не ходит. См. `docs/CONTRACT.md`.

## Две планки, и обе обязательны

Отчёт не собирается, если названа только одна:

| планка | что говорит | чем плоха в одиночку |
|---|---|---|
| **против ВХОДА** | это сделал продукт | тривиально велика: наивный `.cu` идёт на доли процента пика |
| **против СОПЕРНИКА** | абсолютная величина | не отвечает, продукт ли это сделал |
| **доля работы в стене** | потолок сквозного эффекта | без неё «x1.36» превращается в 0.6 % — замеренный случай |

## Реестр законов: почему открытие здесь не протухает

Открытие, записанное только в отчёте, живёт неделю: его нельзя ни найти в точке применения,
ни опровергнуть, ни заметить, что оно уже опровергнуто. Поэтому у **утверждений** здесь та же
дисциплина, что у **чисел** (`Rate`: значение + единица + статус + происхождение):

```
docs/LAWS.md                     ПОРОЖДАЕТСЯ из реестра; расхождение роняет гейт G10
data/laws/*.json                 законы МЕТОДА и ИНСТРУМЕНТА
tempo/plugins/<arch>/data/laws/  законы МАШИНЫ (иначе имя архитектуры протечёт в конвейер)
```

Запись несёт шесть обязательных полей — **формулировка / якорь (отчёт, ЧИСЛА, прибор, карта) /
фальсификатор / область действия / место в продукте / вид** — и два, которых обычно нет:
`bias` (в какую сторону ошибается замер: без него фальсификатор нечестен) и `superseded_by`
(вытеснение вместо удаления — отрицательное знание теряется первым).

Механизм, а не намерение:

| гейт | что делает невозможным |
|---|---|
| **G9** | закон без ОБЛАСТИ, без ФАЛЬСИФИКАТОРА или с чужими процессами на карте |
| **G10** | «внесено» без исполняемого места; «долг» с уже готовой проверкой; проза `docs/LAWS.md`, разошедшаяся с данными |
| **G11** | маркер `LAW=<id>`, не разрешающийся в запись; внесённый закон без ссылки из кода; **возврат опровергнутой формулировки** в дерево |

Опровержение проверяется **обратной** проверкой: у закона место *считает*, у опровержения
считать нечего — оно *говорит*, поэтому его фразы в дереве быть не должно. Цитировать
опровергнутое можно — но только рядом с идентификатором опровергающей записи. Правило
механическое, поэтому списка файлов-исключений (в который со временем попадает всё) нет.

Регистрация висит на артефакте, который и так пишется: отчёт `EV_*.md` несёт блок
`<!--LAW {...} -->`, а `tools/laws_from_reports.py` отказывает, если у блока нет фальсификатора
или области — **и если названного якорем числа нет в теле своего же отчёта**.

Сегодня в реестре **39 записей: 16 законов, 12 опровержений, 11 долгов**
(`python3 -m tempo.cli laws --unwired` печатает невнесённые, `--scope M=64` — действующие в
точке).

## Чего продукт НЕ умеет

Полный перечень с ценами и формами лечения — **`docs/NOT_YET.md`**. Коротко:

1. **Не читает произвольный `.cu`.** Распознаётся объявленная операция.
2. **Не эмитит расписание.** Порядок команд и распределение регистров остаются у стороннего
   компилятора. Разрыв «граница модели против него» **измеряется, а не закрывается** — и
   это ровно тот остаток, который отделяет 0.94 от 1.0 в глубоком префилле.
3. **Модель — ГРАНИЦА, а не предсказание.** Ядро идёт на 61 % собственного счётного потолка;
   четыре правки уронили счёт команд и **не уронили время**.
4. **Модель умеет молчать.** При малом числе строк выхода связывает задержка при низкой
   занятости — канала для неё в модели НЕТ, и отчёт печатает `МОДЕЛЬ МОЛЧИТ` вместо тихо
   неверной границы.
5. **Калибровочная поверхность дополнений пуста** (замеренных кривых 0), поэтому выбор
   «перестановка или дополнение» делается перебором со сборкой.
6. **Формы версии 1:** `C = A*B^T`, половинная точность (или байтовый вес), одинарный
   накопитель, оба операнда k-мажорные, выравнивание 16 байт. Эпилогов нет.
7. **Одна карта, один поток.** Скелетов внимания нет.
8. **Байтовый операнд не даёт счётного выигрыша на sm_70** — там нет целочисленных тензорных
   инструкций, и байт исполняется той же командой. Он покупает **полосу**, а не операции.
   Заявок про «быстрее по счёту» здесь нет и быть не может.
