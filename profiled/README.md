# `profiled/` — ДВОЙНИКИ ЯДЕР: зачем они есть и почему их НЕТ в боевом дереве

Здесь живут **порождённые** копии боевых ядер, размеченные под фазовое профилирование, и
**наложения**, из которых они порождаются. Инструмент: [`../tools/twin.py`](../tools/twin.py).
Профилировщик, который эти двойники потребляет: [`../tools/phaseprof.py`](../tools/phaseprof.py),
правила разметки: [`../tools/fmha_phase.h`](../tools/fmha_phase.h).

```
twin.py check --overlay overlays/X.json          # ворота дрейфа, ничего не порождая; код != 0 при расхождении
twin.py gen   --overlay overlays/X.json          # ворота + порождение в profiled/<имя>/ + manifest.json
twin.py build --twin X --mask 5                  # сборка ОТДЕЛЬНЫМ расширением (свой FA2SM70_BUILD_DIR)
twin.py diff  --twin X --stat                    # чем двойник отличается от БОЕВОГО исходника СЕЙЧАС
twin.py list                                     # что порождено и не протухло ли
twin.py freeze --overlay overlays/X.json --yes   # ПЕРЕзакрепить md5 — только ПОСЛЕ ручной сверки
```

---

## 1. Зачем двойник вообще нужен

Единица анализа ядра — **фаза**, а не команда. Чтобы измерить фазу, её надо **снять**: собрать
заведомо неверное ядро без неё и прочитать время. Одним числом (прежний параметр `DIAG`) снимается
ровно ОДНА фаза — и тогда из замера восстанавливаются только доли `s_i`, а невязка `1 - SUM(s_i)`
остаётся неразделённой: в ней сидит и перекрытие фаз, и работа, которую ни одна фаза не назвала.
Разделяет её только **маска** — возможность снять любую комбинацию:

```
1 = SUM(s_i) + (s_all - SUM(s_i)) + (1 - s_all)          e_ij = s_ij - s_i - s_j
     названное     ПЕРЕКРЫТИЕ        НЕНАЗВАННОЕ
```

Значит в исходнике должна быть маска фаз. Дальше вопрос один: **в каком исходнике.**

---

## 2. Почему НЕ в боевом дереве

Соблазн очевиден: «разметка при маске 0 стоит ноль, пусть живёт в боевом файле». Три причины, по
которым это неверно, и все три уже стоили в этом проекте ложного вывода:

**(а) Расширение пространства инстанцирований.** Маска — новый шаблонный/макро-параметр. Он
размножает варианты ядра: время сборки, размер библиотеки, число путей, которые кто-то может
случайно выбрать номером. У нас это уже происходило: путь выбирается числом (`nosc`, `DIAG`,
`KVFMT`), и число легко приходит из конфигурации. Каждый новый вариант — новая возможность
отгрузить в бой то, что задумывалось как фальсификатор.

**(б) «Нулевая цена» — свойство ОДНОЙ версии компилятора и ОДНОЙ конфигурации, и оно тихо гниёт.**
`if constexpr (false)` действительно не порождает кода — сегодня, на этом ptxas, при этих значениях
параметров. Но проверено это было ровно для одного набора: доказательство «побайтово равно» снимается
на конкретном инстанцировании. Соседнее инстанцирование (другое `d`, другой формат, другая плитка)
никем не проверялось, и когда цена там окажется не нулевой, никто этого не заметит — потому что
никто не перепроверяет то, что однажды объявили бесплатным. В боевом дереве такая правка живёт
годами; в двойнике она порождается заново при каждом замере, и равенство при маске 0 проверяется
тем же прогоном (`twin.py build --mask 0` + побайтовое сравнение cubin с боевой сборкой).

**(в) Главное: в отгружаемом ядре появляются пути, дающие ЗАВЕДОМО НЕВЕРНЫЙ ответ.** Снятая фаза —
это не «медленнее», это неправильный результат: софтмакс без `exp2`, умножение без умножения,
подстановка `0.5 + S` вместо вероятности. Такой путь в боевом бинарнике отделён от боевого одним
целым числом. Достаточно опечатки в конфигурации, унаследованной переменной окружения или
скопированной строки запуска — и сервер честно, быстро и молча считает чушь. Сверка значений это
не поймает: она гоняется на боевом пути, а неверный путь включается другим числом.

Отсюда правило: **фальсификатор не едет в бой.** Он живёт в двойнике.

## 3. Почему копию НЕЛЬЗЯ вести руками

Копия, которую правят руками, расходится с боевым ядром — не «может разойтись», а **расходится**,
потому что боевое дерево живёт: в этом проекте файлы ядер правились по нескольку раз за сутки, и
номера строк из отчётов недельной давности уже недействительны.

Расхождение опасно тем, что оно **бесшумно и правдоподобно**. Устаревший двойник собирается,
считает, даёт доли `35.1 / 19.7 / 15.2 / 5.7 / 2.0 %` — и все они настоящие. Просто они принадлежат
**другому ядру**. Ни один тест на значения этого не ловит (двойник и не обязан давать верные
значения), ни один тест на скорость не ловит (доли внутренне согласованы), а вывод из них делается
про то ядро, которое мы возим. Этот класс ошибок в проекте уже трижды за сутки стоил ложного вывода.

Поэтому двойник **порождается**: хранится не копия, а **наложение** — список правок вида
(файл, ЯКОРНЫЙ ТЕКСТ, замена). Якорь по тексту, а не по номеру строки, именно потому, что номера
едут. А порождение защищено воротами.

## 4. ВОРОТА ДРЕЙФА — то, ради чего инструмент существует

При каждом `check`, `gen` **и `build`** проверяется пять условий. Любое нарушение — падение с явным
сообщением (файл + якорь) и **ненулевым кодом возврата**. Молчаливой сборки устаревшего двойника не
существует:

| # | Что проверяется | Почему это отказ |
|---|---|---|
| 1 | боевой файл существует | наложение ссылается в пустоту |
| 2 | `md5` боевого файла равен закреплённому при порождении наложения | исходник уехал — разметку надо сверить руками |
| 3 | якорь найден | ноль вхождений = правка **молча не применится**, двойник окажется боевым ядром под именем двойника, и «снятая фаза» ничего не снимет |
| 4 | якорь найден **ровно один раз** | два вхождения = правка молча уедет в первое, скорее всего не туда |
| 5 | якоря не перекрываются | две правки метят в один текст |

Ворота **не чинятся автоматически.** Единственный способ узаконить уехавший боевой текст —
`twin.py freeze --yes`, и это **ручной акт после того, как человек сверил разметку с новым текстом**.
`freeze` сам отказывает, если хоть один якорь перестал находиться ровно по разу: иначе он узаконил
бы неверный адрес. После `freeze` все прежние замеры относятся к другому боевому тексту — их надо
перемерить.

Ворота проверены **срабатыванием**, а не рассуждением (подложная копия боевого файла, изменена одна
строка рядом с якорем):

```
(А) md5 уехал                    -> ВОРОТА ДРЕЙФА (md5): ... записан ... / сейчас ...      RC=3
(Б) freeze при ненайденном якоре -> ОТКАЗ: правка #3 -- якорь встречается 0 раз(а)          RC=2
(В) md5 подделан под новый файл  -> ВОРОТА ДРЕЙФА (якорь не найден): ..., правка phase0-gemm1  RC=3
(Г) якорь продублирован          -> ВОРОТА ДРЕЙФА (якорь неоднозначен): ... 2 раз(а), строки 685, 686  RC=3
(Д) дерево уехало ПОСЛЕ порождения, запущен build -> те же ворота, cubin НЕ СОБРАН          RC=3
```

Случай (В) — тот, ради которого якорные ворота стоят **отдельно** от `md5`: если кто-то перезакрепил
`md5`, не глядя, содержательная проверка всё равно ловит правку.

## 5. Наложение: формат

Читаются два вида. Основной — **список по файлам**:

```json
[ { "file":  "fa2_sm70/csrc/volta_fwd_ws.cuh",
    "md5":   "7abb56b280cb5b4162ab90af7aa3e99f",
    "edits": [ { "id": "phase0-gemm1",
                 "why": "фаза 0: первое умножение; затравку аккумулятора оставить СНАРУЖИ",
                 "mode": "replace",
                 "required": true,
                 "anchor":  "<ТОЧНЫЙ фрагмент боевого текста, ровно одно вхождение>",
                 "replace": "<чем он становится в двойнике>" } ] } ]
```

`mode`: `replace` (умолчание) | `insert_before` | `insert_after`. `required: false` — правка,
которую позволено пропустить, если якоря нет (на неоднозначность это послабление не действует).
`id`/`why` читает человек и они попадают в `manifest.json` и в `twin.py diff --stat`.

Второй вид — **словарь**, когда двойнику нужны своё имя, добавочные файлы и сборка:

```json
{ "name": "selftest_ws", "version": "1", "prod_root": "<боевое дерево>",
  "files": [ <записи вида выше> ],
  "write": [ {"path": "inst_ws.cu", "text": "<обвязка инстанцирования>"} ],
  "add":   [ {"path": "fmha_phase.h", "from": "./tools/fmha_phase.h"} ],
  "prod_include_dirs": ["fa2_sm70/csrc", "fa2_src/fmha_kernel", "fa2_src/cutlass/include"],
  "build": { "harness": "inst_ws.cu",
             "steps": [ {"name": "nvcc -cubin", "cmd": "{nvcc} ... {inc} -DFMHA_STRIP_MASK={mask}u -o {outdir}/{name}.cubin {harness}"} ] } }
```

**Копируются только размеченные файлы.** Всё остальное (cutlass, неразмеченные заголовки) берётся
из боевого дерева через `-I`: каталоги двойника идут **первыми**, поэтому размеченный файл
перекрывает боевой одноимённый, а копировать дерево целиком не нужно — и нечему протухать.

`manifest.json` рядом с двойником хранит: `md5` каждого боевого исходника в момент порождения,
**текст каждого якоря** и его строку в боевом файле, время, версию наложения, `md5` самого
наложения. По одному манифесту видно, чем двойник отличается от боевого, даже если наложение
потеряно.

## 6. Сборка — ОТДЕЛЬНЫМ расширением

`twin.py build` ставит свой `FA2SM70_BUILD_DIR = <двойник>/_build_ext/mask<N>/`. Это не удобство, а
защита: боевой кэш `torch.utils.cpp_extension` переиспользует `.so` по имени расширения, и сборка
двойника в общий каталог **вернула бы боевую библиотеку**, а мы бы решили, что померили двойника.
Признак этой ошибки на карте (A/B, сдвинувший метрику на 0.03 %) уже известен из журнала проекта.

Сборка идёт **на процессоре** (`nvcc -cubin` + `cuobjdump -sass`); ядра при этом не запускаются.

## 7. Две мины, из-за которых разметка врёт (обе замерены, обе в силе)

**(1) Компилятор выбросит как мёртвый код всё, что зависело от снятой фазы** — и намеряется
ЧУЖАЯ фаза. В форварде: `vb_run` потребляется только в `rescale_fold`; наивное снятие второго
умножения уносит накопление `vloc` и ВЕСЬ второй канал редукции `sRedS`. Лечение: тело фазы режется
так, чтобы единственный потребитель остался СНАРУЖИ, либо ставится насильный потребитель
(`FMHA_SINK`) / подстановка, сохраняющая зависимость (`0.5f + v` вместо `exp2f(v - m)`).
При снятии ДВУХ фаз каскад сильнее, чем при одной, — иначе `s_all` завышен и перекрытие
посчитается неверно **не из-за железа, а из-за компилятора**.

**(2) Пломба не закрывает CSE:** восемь одинаковых непрозрачных значений склеиваются (замерено:
9 `MUFU.EX2` -> 2). Нужны РАЗНЫЕ подстановки на разные значения.

Обе мины проверяются **статически**, до всякого замера: собрать все нужные маски и посчитать
команды в SASS. Невязка `e_ij = c(i|j) - c(i) - c(j) + c(0)` по HMMA/LDS/STS/MUFU/SHFL/BAR должна
быть нулём; ненулевая невязка — это и есть каскад.

## 8. Самопроверка механизма

`overlays/selftest_ws.json` — минимальное наложение на боевой `volta_fwd_ws.cuh`: две фазы
(бит 0 — первое умножение, бит 1 — второе). Ровно столько, сколько нужно, чтобы показать пару и её
невязку. Измерено на этой машине:

* **цена при маске 0 — ноль, побайтово.** cubin двойника при `--mask 0` и cubin боевого заголовка,
  собранные из одной обвязки, совпадают целиком: `md5 895e82d57e91a00eaa14b0df22061dca` (и SASS
  `3c15c3665d17cd0d2ed1a3aa8ba5843c`). Совпадение cubin сильнее совпадения текста SASS: в него
  входят украшенное имя, распределение регистров и заголовок функции;
* **маска действительно снимает то, что названо:**

  | маска | ВСЕГО | HMMA | LDS | STS |
  |---|---|---|---|---|
  | 0 (боевая) | 2736 | 512 | 174 | 99 |
  | 1 (снят gemm1) | 2200 | 256 | 94 | 99 |
  | 2 (снят gemm2) | 2192 | 256 | 94 | 99 |
  | 3 (сняты оба) | 1664 | 0 | 14 | 99 |

  По 256 `HMMA` на умножение, оба снятия дают ровно 512;
* **каскада в этой паре НЕТ:** `e_01 = c(3) - c(1) - c(2) + c(0)` равна нулю по HMMA, LDS и STS
  (по TOTAL `+8` — общая адресация плитки, которая при снятии обоих умножений умирает целиком).
  Это подтверждает прежний вывод по этому ядру и, главное, показывает **как** он проверяется.

Полная разметка форварда и бэкварда живёт в своих наложениях (`overlay_fwd*.json`,
`bwd/overlay_bwd.json`); самопроверка нужна не вместо них, а чтобы механизм имел собственное
доказательство.

## 9. Границы

* **Боевое дерево — только чтение.** `twin.py` в него не пишет ни байта; проверяется тем, что
  `git -C <боевое дерево> status --porcelain` до и после работы совпадает.
* **Двойника нельзя править руками.** Правки будут стёрты следующим `gen` и — что хуже — не попадут
  в ворота дрейфа. Правьте наложение. Об этом же написано в `note` каждого `manifest.json`.
* **Двойник не даёт верных значений** и не предназначен для сверки точности. Он даёт ВРЕМЯ и СЧЁТ
  КОМАНД при снятой фазе — больше ничего.
