### L-PHASE-SUBADDITIVE

**Формулировка.** Фазы СУБаддитивны: снятие двух фаз по отдельности даёт в сумме больше, чем снятие обеих сразу. Значит набор долей -- это НЕ разбиение, а законная ВЕРХНЯЯ оценка с известной погрешностью 8-13 % относительно, и погрешность УБЫВАЕТ с ростом формы. Всякий инструмент, печатающий набор долей, ОБЯЗАН печатать эту оговорку рядом с числами.

**Якорь** (`EV_additivity.md`). таблица трёх форм: 49.09 %; 43.36 %; +13.2 %; +9.9 %; +8.2 % Статус: `MEASURED`. Карта 0, 1530 МГц, чужих процессов 0, 2026-08-02. Прибор: `scratchpad/b2_additivity.py`.

**Смещение замера.** фальсификатор, снимающий ОБЕ фазы, заведён специально ради этого вопроса. Без него сумма одиночных снятий читалась бы как разбиение -- ошибка в сторону ЗАВЫШЕНИЯ каждой доли.

**Фальсификатор.** пара фаз, где сумма одиночных снятий МЕНЬШЕ совместного (знак перевернулся), либо завышение вне 8-13 % на форме сопоставимого размера _Как:_ четыре варианта (база, без первой, без второй, без обеих), чередование ВСЕХ ЧЕТЫРЁХ внутри раунда, медиана по девяти раундам _Цена:_ одна сборка с фальсификатором, снимающим обе фазы

**Область действия.** kernels=проверено на ОДНОМ теле  phases=проверено на ДВУХ фазах из пяти  НЕ: другие пары фаз без перепроверки тем же приёмом; аддитивность есть свойство РЕЖИМА, а не закона

### L-BW-VERDICT-ONE-WAY

**Формулировка.** Вывод «полоса НЕ связывает» СТРОГИЙ, обратный -- условный: трафик внекристальной памяти считается при НУЛЕ попаданий кэша второго уровня, то есть это оценка СВЕРХУ. Поэтому инструмент обязан печатать ПОРОГ: при какой доле попаданий вывод перевернулся бы.

**Якорь** (`EV_relayout_v1.md`). 2.2 порог доли попаданий: 60.1 %; 97.70 % Статус: `MODEL`.

**Смещение замера.** оценка СВЕРХУ по построению. Ошибка идёт в сторону вывода «полоса связывает», поэтому отрицательный вывод строг, а положительный требует доли попаданий.

**Фальсификатор.** тело, у которого вывод «полоса не связывает» перевернулся при доле попаданий ВЫШЕ напечатанного порога _Как:_ прибор на семье тел, доля попаданий рядом с порогом _Цена:_ один прогон прибора, нужны права на профилировщик

**Область действия.** applies=любое тело  НЕ: вывод «полоса связывает» -- он условен и без доли попаданий не годится

**Где живёт в продукте.**

### L-TWO-MODELS-OCCUPANCY

**Формулировка.** В дереве живут ДВЕ модели каналов, и занятость входит в них ПО-РАЗНОМУ: у стенда обе нагрузки линейны по числу варпов (x W и x W/4, отношение постоянно), у конвейерной границы варпы входят только в канал процессора, а канал планировщика от них не зависит вовсе. Значит связывающий канал у конвейерной границы с занятостью МЕНЯЕТСЯ, а у стенда -- нет, и опровержение L-OCCUPANCY-MOVES-BINDING проверено ТОЛЬКО на стенде.

**Якорь** (`EV_relayout_v1.md`). 3.3 занятость и связывающий канал: DRAM 100; MIO 36 Статус: `MODEL`.

**Смещение замера.** расхождение НАЙДЕНО проверкой запрещённых формулировок, а не замером на железе, и остаётся утверждением о ДВУХ НАШИХ МОДЕЛЯХ, а не о машине. Прогон конвейерной границы при 8/16/32 варпах СДЕЛАН и подтвердил: отношение канала планировщика к каналу процессора падает РОВНО вдвое на удвоение занятости (у стенда оно постоянно). Какая из двух арифметик верна для ЖЕЛЕЗА, этим не решается.

**Фальсификатор.** отношение каналов на конвейерной границе, НЕ падающее вдвое на удвоение занятости: тогда расхождение мнимое и одна из двух арифметик описана неверно. Отдельно и дороже: замер на железе, называющий, КАКАЯ из двух арифметик верна _Как:_ один и тот же набор атомов через границу при трёх значениях числа варпов, доли каналов рядом; карта не нужна _Цена:_ три вызова, карта не нужна

**Область действия.** applies=обе модели каналов дерева  warps=8..32  НЕ: утверждение о ЖЕЛЕЗЕ -- это утверждение о ДВУХ НАШИХ МОДЕЛЯХ

### L-INT12-IS-ONE-ELEMENT

**Формулировка.** Знаковое 12-разрядное целое лежит в ОДНОМ элементе половинной точности (знак -- двенадцатый разряд), поэтому 12 бит стоят РОВНО столько же вызовов тензорной операции, сколько 8, 11 или 16; минимальная мера вызовов -- ceil(p/12)/4. Законен ТОЛЬКО симметричный код: асимметричный край уже округляется.

**Якорь** (`EV_int12_prim.md`). 2. ИСЧЕРПЫВАЮЩИЙ ГЕЙТ: 4096; 32768; 0 расхождений; 2.25 Статус: `MEASURED`. Карта 0, 1530 МГц, чужих процессов 0, 2026-08-02. Прибор: `EV_int12_gate.cu`.

**Смещение замера.** гейт ИСЧЕРПЫВАЮЩИЙ по коду (перебор всех 4096 значений), но домен точности накопителя проверен до конечной суммы. Вне объявленного домена утверждения нет.

**Фальсификатор.** ОДНО расхождение в переборе всех 4096 кодов, либо одно расхождение тензорного произведения с целочисленным внутри объявленного домена точности _Как:_ побитовое сравнение с кодировкой половинной точности и точное равенство в целых 64 разрядов; никакого «почти» -- одно расхождение убивает схему целиком _Цена:_ один прогон гейта, свободная карта

**Область действия.** acc=одинарная точность  arch=sm_70  ceiling=~19 разрядов при K=4096 (шум sqrt(K/4)*2**-24); точнее -- только древовидной редукцией  code=симметричный  exact_while=|сумма| < 2**24  group=8 (либо 4, тогда 2.5 действия на элемент)  НЕ: асимметричный код; суммы вне домена точности накопителя

**Где живёт в продукте.**

* `tools/bits_table.py` -- случай_самопроверки, символ `fp16 точен по ВСЕМ целым до 2048`
* `tools/bits_table.py` -- случай_самопроверки, символ `asym int12 (код 4095) НЕ представим точно`

### L-STREAMS-FREE

**Формулировка.** При равном суммарном объёме один, два и три СПЛОШНЫХ потока чтения дают одну и ту же полосу (разброс 0.2 %, шум): плоскостная раскладка не платит за число потоков.

### L-REG-WIDTH-NOT-NAMES

**Формулировка.** Единица счёта регистрового давления -- ЯЧЕЙКА, а не ИМЯ регистра: операнд занимает столько подряд идущих регистров, какова его ширина (тензорный HMMA.884 -- 2 у всех четырёх операндов, обращение с суффиксом .128 -- 4, .64 -- 2, адрес в глобальном/общем пространстве -- 2, в разделяемом -- 1, IMAD.WIDE -- 2 только у приёмника). Счёт по именам занижает потребность ВДВОЕ и даёт вывод «влезает» там, где сборщик разливает: на пяти телах модель давала 112-121 при ptxas 232-255 и называла влезающими оба тела, разлившие 32 и 56 байт. Таблица ширин проверяется САМИМ машинным кодом: операнд шириной w обязан начинаться с номера, кратного w -- 12554 вхождения, невыровненных 0. R_треб = MaxLive(по ширине, циклически) + РАЗЛИТОЕ(из опкодов LDL/STL) + 7; на телах без разлива ошибка -7..+1 регистра при ptxas 232/250/248, на разлившихся величина достигает потолка (265 и 255 при потолке 255). Вывод АСИММЕТРИЧЕН: «разольётся» -- строгий, «влезает» -- условный, потому что считан МЕЙНЛУП, а сборщик распределяет регистры на всё ядро.

**Якорь** (`EV_packer_debts.md`). долг 1: ширина регистрового операнда: 117; 244; 250; 265; 12554; 93 Статус: `SASS`. Прибор: `tools/relayout.py --gate-regs`.

**Фальсификатор.** тело, у которого ptxas объявил разлив, а R_треб по ширине НЕ достиг потолка (или обратно: R_треб превысил потолок, а кадр стека 0); либо ненулевой счёт невыровненных операндов -- он означает, что таблица ширин неверна _Как:_ python3 tools/relayout.py --gate-regs -- пять тел с известными четырьмя числами ptxas; счётчик выравнивания печатается там же _Цена:_ ни карты, ни сборки: всё читается из машинного кода
